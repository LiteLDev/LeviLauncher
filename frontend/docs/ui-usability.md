# UI 操作与异常状态回归

启动器沿用 `surface` 等语义材质和统一 `ROUTES`。侧栏固定为启动、下载、实例列表、关于、设置五项；内容和模组从主页进入，下载任务从下载页进入。应用外层固定为窗口高度，各页面负责内部滚动；个性化分区导航在滚动时保持可见。

## 自动检查

在 `frontend` 目录执行：

```sh
npm run test:usability
npm run test:explorer
npm run build
```

`test:usability` 执行真实的目录与玩家工具函数，验证权限失败传播、重试恢复和空根目录行为。生产构建同时检查类型、材质和包体积。

## 浏览器预览

```sh
npm run dev:ui-review
```

预览只监听 `127.0.0.1:5174`。测试配置替换生成绑定中的调用，返回模拟目录和进程，不执行真实的进程终止、文件写入、安装或下载。页面右下角有测试标识；“恢复模拟接口”用于从故障场景恢复，再点击产品内的重试按钮。该配置拒绝生产构建，常规开发和构建不加载模拟接口。

测试来源独立于桌面应用。初始化的主题、引导和协议状态仅是这个本地预览来源的测试数据。以下路径是测试地址，产品导航仍使用路由常量。

| 测试地址 | 验收内容 |
| --- | --- |
| `http://127.0.0.1:5174/?scenario=normal#/settings` | 搜索“亮度”定位壁纸分区；离开后返回保留设置分区；无效目录 `C:\invalid` 保存失败后可放弃离开 |
| `http://127.0.0.1:5174/?scenario=process-error#/settings` | 其他设置 → 扫描进程 → 结束所有进程：先确认，再显示错误并保留未结束进程；恢复模拟接口后可再次执行 |
| `http://127.0.0.1:5174/?scenario=root-error#/onboarding` | 目录未确认时禁止完成；恢复模拟接口并重试后可继续 |
| `http://127.0.0.1:5174/?scenario=players-error#/content/worlds` | 玩家目录读取失败有持续错误和重试，不显示为空列表 |
| `http://127.0.0.1:5174/?scenario=worlds-error#/content/worlds` | 世界目录读取失败；恢复后重试展示存档 |
| `http://127.0.0.1:5174/?scenario=partial#/content/worlds` | 展示健康存档，同时列出未能读取的存档文件夹 |
| `http://127.0.0.1:5174/?scenario=servers-error#/content/servers` | 服务器读取失败有持续错误和重试 |
| `http://127.0.0.1:5174/?scenario=downloads#/download/tasks` | 三种任务状态、筛选数量、重试保留校验参数、打开目录，以及已完成任务进入对应安装页 |
| `http://127.0.0.1:5174/?scenario=wallpaper#/settings` | 个性化 → 壁纸：数字输入可清空后输入 `80`，失焦后亮度滑块同步为 `80` |

至少检查 960×600 和常用桌面尺寸、浅色和深色主题、固定五项侧栏、顶部导航。长页滚动后切换页面，标题应仍在顶栏下方可见。

浏览器验收不能替代 Windows 桌面集成测试。真实的进程权限、目录权限、系统文件选择器和游戏安装仍需在桌面版中确认。
