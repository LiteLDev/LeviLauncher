# 設定とカスタマイズ

LeviLauncher は、パス、外観、コンポーネント管理、プライバシー設定、更新戦略を調整するための、比較的包括的な設定ページを提供しています。

## 主な設定セクション

現在、アプリケーションは設定を以下のセクションに分類しています：

- 基本設定
- 個人用設定
- サードパーティ製コンポーネント
- その他
- プライバシー
- アップデート
- 情報

## 調整できる項目

### パスとストレージ

- 基本コンテンツパス
- ホストファイルが置かれる書き込み可能な場所
- あなたのディスク構成により適した環境配置

### 外観

- 言語
- ライト/ダークテーマのプリファレンス
- テーマカラーの動作
- 背景および視覚的な個人化項目

#### 壁紙とインターフェイスのマテリアル

**個人用設定 → 壁紙 → 背景画像** で画像フォルダーを選び、**個人用設定 → マテリアルと読みやすさ** を開いて、壁紙とコンテンツの間のレイヤーである **インターフェイスのマテリアル** を調整します。ナビゲーション、カード、タブ、フォームコントロール、ポップアップのサーフェスは 1 つのマテリアルシステムを共有します。ライトとダークのプロファイルは別々に保存され、アプリのテーマに合わせて自動的に適用されます。マテリアルエディターの **ライトモード** / **ダークモード** ボタンは、編集・プレビューするプロファイルを選ぶだけです。

| 設定 | 動作 |
| --- | --- |
| バランス | 既定のプリセット：読みやすさの保護をオンにしたソフトなガラス |
| クリア | カード越しに壁紙がより多く見え、読みやすさの保護はオフ。シンプルでコントラストの低い画像に最適 |
| ソリッド | カードのぼかしがない不透明なカード。カードの外側では壁紙が見えたまま |
| インターフェイスの不透明度 | テキスト、アイコン、ボタンを薄くせずに、インターフェイスのニュートラルなサーフェスの色合いを変更 |
| インターフェイスのぼかし | パネル、ナビゲーション、ポップアップの背後のぼかしを制御。画像のぼかしは壁紙全体に影響 |
| 壁紙のオーバーレイ | 画像の明るさや不透明度とは別に、ライトモードでは明るい色合い、ダークモードでは暗い色合いで壁紙を和らげる |
| 読みやすさの保護 | テーマ、明るさ、画像の不透明度、ぼかしに基づいて控えめな最小限の色合いを適用し、補助テキストを強調 |

ライブプレビューは、読み込まれた画像とレンダリングパラメーターをメインウィンドウと共有します。保護によって実際のカードの不透明度が上がると、エディターには適用された値が表示されます。この計算で画像が解析されたりアップロードされたりすることはありません。**このテーマをリセット** は編集中のマテリアルプロファイルのみを元に戻し、画像フォルダーやもう一方のテーマのプロファイルは消去しません。

フォルダーに複数の画像がある場合は **次の画像** を使用します。**順次** は自然なファイル名順で並べ、**ランダム** は現在の画像の繰り返しを避けます。画像が選択されていない、画像を読み込めない、または画像の不透明度が 0 の場合、インターフェイスは通常のサーフェスに戻ります。ハイコントラスト、透明度の低減、サポートされていない背景フィルターの場合は、不透明なフォールバックサーフェスが使用されます。

### サードパーティ製コンポーネント

- [lip](https://github.com/LiteLDev/lip) のステータス：確認、インストール、更新、キャッシュの削除

### プライバシー

- 匿名の利用状況分析（Microsoft Clarity）。いつでもオフにできます
- Clarity の利用規約と Microsoft のプライバシーに関する声明へのリンク

### アップデート

- 更新チェック
- **ベータ版アップデートを受信**：ランチャーのプレリリース版アップデートを受け取ります

## 推奨されるデフォルト値

- ホストファイルは、書き込み可能で空き容量が十分にあるディスクの場所に置く
- ランチャーのプレリリース版ビルドが必要な場合を除き、**ベータ版アップデートを受信** はオフのままにする
- 外観を細かく調整する前に、まず基本環境を安定させる

## 設定を再確認する価値があるタイミング

以下の状況に遭遇した場合は、設定ページを確認することをお勧めします：

- インストールを別のディスクに移行したい場合
- 書き込み権限のエラーが発生した場合
- 異なるマシンで異なる外観やパス戦略を使用したい場合
- ダウンロードまたはコンポーネントの識別に関する問題をトラブルシューティングする必要がある場合
